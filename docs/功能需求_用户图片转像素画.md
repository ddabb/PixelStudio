# 像素画工作室 · 功能需求：用户图片转像素画

> 状态：**已实现（v1.6.0，P0+P1 合并交付）** ／ 提出：2026-11-05 ／ 实现：2026-11-06 ／ 基线：v1.2.0 + 选色修复补丁（160=160 字符串键、40 文件 0 超 900 行、单测 192 例）。执行记录见 §13。
> 承接条款：主计划 §4.1 P1「PNG 导入为图层（最近邻缩放）」→《1.0.1优化计划》P9 余项 →《1.2.0版本内容》§3「统一顺延下一版本」。
> 底线不变：**零网络权限、全离线、买断制、纯本地确定性算法**。本需求是图像处理，**不是 AI 生成 / 风格化 / 云端推理**（主计划 §4.2、各版本「非目标」条款继续有效）。

## 1. 背景与问题

- 当前创作入口只有「从零绘制」：列表页 `project_new` → 空白 `PixelDoc(w,h)` → 编辑器落笔。用户已有的照片、头像、Logo、手绘稿无法直接变成可编辑的像素稿，起步门槛高。
- 与 PocketToolbox 类工具的差别：本应用输出的是**可继续编辑的 .pxs 工程**（图层/帧/调色板/撤销/导出全套可用），不是一张只可保存的成图。
- 现有能力盘点（复用为主，缺的是「入向链路」）：

| 已有 | 位置 | 本需求用途 |
| --- | --- | --- |
| RGBA 像素真源（0xAARRGGBB packed） | `core/PixelBuffer.ets` | 转换结果直接 `cel.data.set()` |
| 文档模型（≤8 层 / 单帧多 cel） | `core/PixelDoc.ets` | 生成工程 / 导入为图层 |
| 最近邻整数倍放大 + 网格线 | `core/Resample.ets` | **只有放大，需补缩小**；导出链沿用 |
| 加权最近色映射（d²=2Δr²+4Δg²+3Δb²） | `core/BeadQuantize.ets` | 按调色板量化的口径基线 |
| 15-bit 分桶中位切分量化 | `core/GifCodec/GifEncoder.ets` `quantizeToPalette()` | 自动色板模式可抽公共内核 |
| 6 套预置/自定义调色板 + 拼豆品牌 | `core/Palettes.ets` / `viewmodel/PaletteStore.ets` | 量化色目标 |
| .pxs + 缩略图 + 原子落盘 + 自动保存 | `core/PxsFile.ets` / `viewmodel/ProjectStore.ets` | 结果工程落盘，**格式零改动** |
| CelEntry 快照撤销（16MB 预算自适应） | `core/UndoStack.ets` / `viewmodel/DocOps.ets` | 导入动作可撤销 |
| 系统选择器免权限读写 | `components/BackupDialog.ets`（`picker` from `@kit.CoreFileKit`） | 选图入口的成熟先例 |

## 2. 目标与成功指标

| 编号 | 目标 | 可度量口径 |
| --- | --- | --- |
| G1 | 用户选一张本地图片，3 步内得到可编辑的像素画工程 | 选图 → 参数预览 → 确认，中途可反悔且零副作用 |
| G2 | 转换结果是「真像素稿」 | 输出恒为 N×N 整数网格、无插值糊边、无半透明脏色（alpha 二值化） |
| G3 | 确定性、可回归 | 同一原图 + 同一参数 → 输出 RGBA 逐字节一致（单测锁定） |
| G4 | 隐私与版本底线 | module.json5 零新增权限、无 INTERNET；原图不落盘、不上传、不写入 .pxs |
| G5 | 性能可接受 | 64² 端到端 <1s、256² <2s（模拟器口径，待实测）；解码峰值 ≤16MB |

## 3. 范围与优先级

| 级别 | 内容 | 说明 |
| --- | --- | --- |
| **P0（MVP）** | 列表页「从图片新建」：选图 → 参数面板 → 实时预览 → 生成单帧单图层新工程并进入编辑器 | 独立对话框组件，编辑器页零改动（见 §5.4） |
| **P1** | 编辑器内「导入为图层」：在当前活动帧新增一层写入转换结果 | 兑现 P9「PNG 导入为图层」原条款；受 `MAX_LAYERS = 8` 约束 |

## 4. 用户故事

- **US-1（主）**：作为想做头像的用户，我从相册选一张照片，选 64×64 / 居中裁切 / PICO-8 色板，预览满意后点「生成」，直接进入编辑器继续修线稿、加帧、导出 PNG。
- **US-2**：作为已有工程的用户，我在编辑器把一张参考图导入为**新图层**，描完可隐藏/删除该层；误导入时一步撤销即可回退。
- **US-3**：作为在意隐私的用户，全程无联网、无权限弹窗，原图不会被保存进工程文件，取消选择后不留任何空工程或临时文件。

## 5. 交互规格（P0）

### 5.1 入口与流程

1. 列表页顶栏 `project_new` 旁新增「图片转像素」按钮（新字符串键 `import_entry`），点开 `components/ImageImportDialog.ets`（scrim 全屏遮罩，仿 `BackupDialog` / `TextToolDialog` 单挂载）。
2. 「选择图片」→ 系统选择器（**免权限**：优先 `photoAccessHelper.PhotoViewPicker`；若不可用回退 `picker.DocumentViewPicker`，与 `BackupDialog` 同链路）。
3. 参数面板 + **并排实时预览**（原图缩略 / 像素结果），改参数即时重算；预览用 `image.createPixelMapSync` RGBA_8888 走现有渲染口径。
4. 「生成工程」→ 落盘 → 跳编辑器；「取消」/ 返回键 → 先收对话框（与 `EditorPage.onBackPress` 文本框规则一致），不产生任何工程。

### 5.2 参数表（P0 冻结项）

| 参数 | 取值 | 默认 | 备注 |
| --- | --- | --- | --- |
| 输出尺寸 | 16/24/32/48/64/96/128/192/256（复用 `ProjectListPage.NEW_SIZES`，正方形） | 64 | 上限 256 与 `PXS_MAX_CELLS=65536` 一致 |
| 适配方式 | 居中裁切 cover / 完整留边 contain | cover | contain 留边默认透明 |
| 采样 | 区块面积平均 box-average / 中心取样 nearest | 面积平均 | 面积平均按 alpha 加权，避免透明边缘发黑 |
| 色彩模式 | 不量化（保留缩采样真彩）/ 按当前调色板 / 指定预置或自定义调色板 / 拼豆品牌色板 / 自动色板 | 按当前调色板 | 色板名沿用 `palette_name_*` 本地化 |
| 自动色数 | 4 / 8 / 16 / 32 / 64 | 16 | 仅「自动色板」模式可见 |
| 抖动 | 关 / Bayer 4×4 有序抖动 | 关 | 固定阈值表，量化前对 RGB 加偏置 |
| 透明 | 保留 alpha / 填充背景色（默认白） | 保留 | alpha <128 → 全透明，≥128 → 不透明 |
| 工程名 | 默认「图片像素画」（新键 `import_name_default`），可改 | — | 与 `project_name_default` 同口径 |

### 5.3 确认前约束

- 确认前**不写工程、不改现有文档、不落任何临时文件**；所有中间态只在内存缓冲。
- 失败/取消统一双语 toast（`import_failed` / `import_cancelled`），静默降级不崩；用户取消选择器按正常取消处理，不弹错误。

### 5.4 落地路径（推荐方案）

> 列表页对话框内：`ImageImport` 纯函数产出 N×N RGBA → `new PixelDoc(N,N)` 写入 `Layer 1` → `ProjectStore` 存 `.pxs` + `.thumb` → `EditorLaunch.openExisting(id)` → `pushUrl('pages/EditorPage')`。

- **首选**：先落盘再走「打开既有工程」，**完全不动 `EditorLaunch` 字段与 `EditorPage.aboutToAppear`**，风险最低，且天然享受 30s 自动保存 / 杀进程恢复。
- 备选（不推荐）：扩 `EditorLaunch` 携带预计算 RGBA，由编辑器新建分支注入；会动到 816 行的 `EditorPage.ets`，且要处理静态字段生命周期。
- P1「导入为图层」另走 `DocOps` 新增入口：新增层 + `UndoStack.entryIfChanged(cell.data, before)` 生成 `CelEntry`，与 `insertText` 同构；导入前先 `stopPlay`（仿 `DocOps.stopPlay`）。

## 6. 处理管线（算法规格，纯函数可测）

| 步 | 规格 |
| --- | --- |
| ① 解码 | 选择器 uri → `fs.openSync` → `image.createImageSource` → `PixelMapFormat.RGBA_8888` → `readPixelsToBuffer`。超大图先按 `DesiredSize` 限边（建议 ≤2048），**不得整图 4000×3000×4 直接进内存**；格式白名单见 §11。 |
| ② 几何适配 | cover：等比缩放至短边贴合后居中裁切；contain：等比缩放内接 + 透明留边并居中。只做整数像素对齐，不做旋转/自由裁切。 |
| ③ 缩采样 | 新增纯函数（建议 `core/ImageImport.ets`，或扩 `Resample` 增加 downscale）：对每个输出格映射源区块，`box-average` 按 alpha 加权求 RGB 均值 / `nearest` 取区块中心像素。输出 N×N RGBA，长度必须 = w*h*4，非法参数直接拒收（沿用 `Resample.scaleNearest` 的校验风格）。 |
| ④ 量化 | 按调色板：沿用 `BeadQuantize.nearestIndex` 加权距离与「同距取小索引」确定性规则；自动色板：复用/抽取 `GifEncoder.quantizeToPalette` 的 15-bit 分桶中位切分内核。透明像素不参与色板统计；输出 alpha 二值化，不产生半透明。抖动为量化前固定 Bayer 4×4 偏置。 |
| ⑤ 写入 | `PixelDoc(N,N)` 单帧单图层 → `cel.data.set(rgba)` → `ProjectStore` 落盘（`.pxs`/`.thumb` 格式零改动）。P1 图层路径同上 + `CelEntry` 入栈。 |

**不变量**：① 纯函数不修改输入缓冲；② 同输入 + 同参数输出逐字节确定；③ 原图只在内存，转换结束 `pixelMap.release()` 释放；④ 全程无网络调用。

## 7. 权限与隐私（硬约束）

- 系统选择器选图**免权限**（先例：`BackupDialog` 的 `DocumentViewPicker`）；`module.json5` 保持现状（仅 `ohos.permission.VIBRATE`），**不新增** `READ_IMAGEVIDEO`、**不声明** `INTERNET`。
- 原图不写入沙箱、不缓存、不进 `.pxs`；工程只存转换后的 N×N 像素。隐私政策「不收集、不存储、不上传任何用户数据」口径不变。
- 需在模拟器实测：选择器 API 可用性、uri 读权限、`ImageSource` 对 EXIF 方向的处理（列入 §11）。

## 8. 异常与边界（失败零副作用）

| 场景 | 要求 |
| --- | --- |
| 用户取消选择器 / 取消对话框 | 静默返回，不建空工程、不留 `.tmp` |
| 不支持/损坏的图片、解码失败 | `import_failed` toast，文档与列表原样 |
| 超大图 / 极端长宽比 / 全透明图 | 限边解码；极端比例给可读提示或按 contain 兜底；全透明输出全透明画布不崩 |
| 色板为空 / 自动色数越界 / 尺寸非白名单 | 参数校验拒收，回退默认，不抛未捕获异常 |
| P1 导入为图层时已达 8 层 | 提示「图层已满」，不覆盖现有层（与 `PixelDoc.addLayer` 返回 undefined 一致） |
| 播放中 / 自动保存进行中导入 | 先停播；落盘与自动保存顺序化，不并发写同一 .pxs |
| 低存储 / 落盘失败 | 不留下损坏工程（沿用 `ProjectStore` 原子写 + 损坏灰显） |

## 9. 性能与工程护栏

- **内存**：解码缓冲 ≤2048²×4≈16MB + 输出 ≤256²×4=256KB；预览复用单一缓冲，及时 `release()`。
- **耗时**：64² <1s、256² <2s（模拟器实测口径，参考主计划 §6.5 预算）；参数变化重算需防抖，UI 不卡顿，慢路径给出 `import_busy` 提示。
- **文件行数**：`code_stats.py --check` 必须全绿（当前 40 文件 0 超 900）。新逻辑拆成 `core/ImageImport.ets`（算法纯函数）+ `components/ImageImportDialog.ets`（UI），**禁止把 UI 与算法继续堆进 613 行的 `ProjectListPage.ets` / 816 行的 `EditorPage.ets`**。
- **双语**：新键统一 `import_` 前缀，`base/en` 同步，`check_strings.py --check` 全绿（当前 160=160）。
- **单测**：模拟器 `hdc shell aa test -b com.ddabb.pixelstudio -m entry_test -s unittest OpenHarmonyTestRunner -s timeout 15000`；新增用例覆盖 box-average / nearest、cover / contain 对齐、最近色同距确定性、alpha 二值化、抖动确定性、非法尺寸拒收、同输入逐字节一致；基线 192 例不得回归。
- **构建**：任务结束前 `build_project` 成功（default + `entry@ohosTest` 双绿）。

## 10. 验收标准

1. 相册选图 → 调参 → 预览 → 生成 → 编辑器可继续落笔、加帧、改色、导出 PNG，全程 ≤3 次主动操作。
2. 输出 N×N 网格无插值糊边；量化模式下无半透明像素，透明区域在棋盘格底正确显示。
3. 同一图片 + 同一参数两次转换，解码 `.pxs` 像素流逐字节一致。
4. 新建工程走「先落盘再打开」：退出重进、杀进程恢复后工程与缩略图完整。
5. P1 导入为图层：新增层、8 层上限提示、一次撤销回到导入前像素（撤销按钮 enabled→正确置灰）。
6. 取消 / 解码失败 / 低存储：列表数量不变，无空工程、无临时残料、无崩溃。
7. 中英文与深色模式全量覆盖新文案；对话框 scrim 不误触底层按钮，返回键先收框。
8. `module.json5` 零新增权限；抓包/权限清单复核无网络调用，关于页「离线」描述仍成立。
9. 64² / 256² 耗时与内存达标（实测记录，不以目测代替）。
10. 护栏双绿 + 单测全绿 + default/ohosTest 构建双绿。

## 11. 版本协调与开放问题

- **版本建议**：随下一版位（v1.3.0 候选，versionCode 规则 1003000）交付 P0 + P1 合并批次；§16 图标生成器与选区旋转翻转、混合模式、16 层、图集 padding 等同属顺延项，需另行排优先级。定价维持 ¥12 买断，不单独提价。
- **与 §16 的边界**：§16 是「空白稿 + 模板/遮罩 + 多尺寸导出」，本需求是「已有图 → 像素稿」，两者互补不重叠；后续可组合成「照片 → 像素头像 → 圆形遮罩 → 16/48/512 一键导出」。

| # | 待拍板问题 | 建议 |
| --- | --- | --- |
| Q1 | MVP 只做「新建工程」，还是同时交 P1「导入为图层」 | 建议同批交付，共用同一算法内核，边际成本低 |
| Q2 | 是否保留「自动色板（中位切分）」模式 | 建议保留，但需先验证 `GifEncoder` 量化内核可安全抽出而不影响 GIF 导出 |
| Q3 | 图片格式白名单 / 最大边长 | 建议 PNG/JPEG/WebP + 2048 限边；GIF 只取首帧或拒收 |
| Q4 | contain 留边默认透明还是白底 | 建议透明（与棋盘格底/拼豆空钉位口径一致） |
| Q5 | 是否需要亮度/对比/饱和预调 | 建议 P1，先保证主链路 |
| Q6 | 非正方形输出（如 128×96） | `EditorLaunch` / `PxsFile` 已支持 w≠h，仅 `NEW_SIZES` 是正方形档；建议 P1 再放开 |
| Q7 | EXIF 方向、HDR/广色域图 | 需模拟器实测 `ImageSource` 行为后定，必要时按 sRGB 8bit 归一 |

## 12. 非目标（重申 + 本需求专属）

- 不做云同步 / 社区 / 账号体系；不做订阅 / 广告 / 内购解锁；不加任何网络权限。
- **不做 AI 生成 / 云端风格化 / 模型推理**（纯本地确定性算法，确定性可单测锁定）。
- 不做人像美颜、智能抠图、自动描边；不做矢量 / 抗锯齿自由绘画。
- 不做视频转 GIF、批量多图（PocketToolbox 域 / P2）。
- 不改 `.pxs` / `.thumb` 格式，不破坏旧工程读取；不改导出链路既有行为。

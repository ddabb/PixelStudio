# 像素画工作室 · 修复记录：画笔颜色一致性与十六进制选色

> 基于 v1.2.0（versionName 1.2.0 / versionCode 1002000）的补丁修复批次。
> 问题：「页面画笔颜色和绘制效果不一致」——调色板面板选色后落笔仍是旧颜色；
> 需求：增强十六进制（HEX）选色并确认「最近选的颜色」记录能力。
> 修复基调：**面板所见颜色 = session.color = 实际绘制颜色，选色即时生效、无独立「应用」步骤。**

## 1. 问题与根因

### 1.1 用户现象

在调色板面板调节 HSB 滑条或输入 HEX 后，预览块/滑条/HEX 框已显示新颜色，
关闭面板落笔绘制却仍是旧颜色——「页面画笔颜色和绘制效果不一致」。

### 1.2 根因一：PalettePanel「预览-提交」双模式并存（主因）

- 面板内 HSB 滑条 / HEX 输入 onChange 仅更新本地 @Local（hue/sat/bri/hexText），
  **不写 session.color**；必须显式点击「应用」按钮才提交（applyPicker）；
- 而 PaletteBar 色卡、PalettePanel 色卡/最近色点击是「立即生效」（直接写 session.color）；
- 两种交互模式并存，用户按直觉调节后关面板即认为已生效 → 显示色 ≠ 绘制色。

### 1.3 根因二：半透明色 HEX 往返丢 alpha（次因）

- 吸管 applyPick 接受任何 a>0 的合成像素 → session.color 可为半透明 0xAARRGGBB；
- 但 ColorUtil.toHex 恒输出 6 位 "#RRGGBB"（丢 alpha）、parseHex 仅认 6 位：
  - HEX 框显示不含透明度 → 与实际绘制（带半透明）不一致；
  - recents/自定义调色板持久化（palettes.txt）中半透明色重启后变全不透明。

## 2. 修复内容

### 2.1 选色即时生效（components/PalettePanel.ets）

- **HEX 输入**：onChange 解析合法（parseHex 成功，6/8 位均可）即提交 session.color
  （applyColor，alpha 保留），滑条/预览经 @Monitor('session.color') → syncPicker 反向同步；
- **HSB 滑条**：拖动中实时预览（本地 hue/sat/bri + hexText + 预览块变色）；
  松手（SliderChangeMode.End）或点击轨道（Click）才提交 session.color（applyPicker）——
  拖动中间色不写入，避免污染「最近使用」recents；
- **移除「应用」按钮**：实时生效后按钮冗余，删除按钮与 palette_apply 资源键
  （base/en 双删，防死资源）；
- **syncPicker 防打断**：外部色变化同步时，若 hexText 已是该色的合法 6/8 位表示
  （parseHex(hexText) === session.color）则不重写，避免打断输入中的光标/大小写。

### 2.2 十六进制 8 位支持（core/ColorUtil.ets）

- parseHex 支持 "#RRGGBB"/"RRGGBB"（不透明，alpha=0xFF）与 "#AARRGGBB"/"AARRGGBB"
  （含透明度，大小写不限）；7 位等非法长度仍拒收；
- toHex：alpha=0xFF 仍输出 6 位（与旧数据/旧版本兼容），alpha≠0xFF 输出 8 位——
  半透明色 HEX 往返无损，吸管取半透明色后面板显示与绘制一致；
- 持久化兼容：palettes.txt 旧 6 位数据原样可读；8 位 token 仅在半透明色时出现，
  旧版本 App 读取时 parseHex 失败静默跳过（不崩、仅丢半透明项）。

### 2.3 最近选的颜色（现状确认，无需新增）

「最近使用 8 色」链路已完整存在，本批确认并加固：

- 记录入口：EditorPage @Monitor('session.color') → PaletteStore.pushRecent
  （去重置顶、容量 8），色卡/HEX/HSB 松手/吸管每次选色即记录；
- 展示：PalettePanel「最近使用」色卡行；
- 持久化：palettes.txt `@recents|#HEX,…` 行，退出落盘、启动恢复；
- 本批加固：HSB 滑条「拖动预览、松手提交」策略保证拖动调色不把中间色灌入 recents；
  toHex/parseHex 8 位支持保证半透明最近色重启后不丢 alpha。

## 5. 追加修复（1.2.3，2026-11-07）：广色域屏「绘制颜色与画笔颜色不一致」（送显偏色）

### 5.1 用户现象与排查

- 现象：新建工程 → 画布 → 直接切换画笔颜色（PaletteBar 色卡/面板选色）→ 落笔绘制，
  画布上笔迹颜色与画笔所选颜色视觉不一致（广色域屏如 Mate70 上更明显）。
- 排查结论：数据链路全程直读 `session.color`（PaletteBar/PalettePanel 点击即写 →
  CanvasView.strokeArgb/Raster.stamp/drawLine 直写 RGBA → Compose 合成快路径覆盖），
  绘制像素数据与所选色**严格一致**；历史修复（§2 选色即时生效 + §2.2 HEX 8 位）无回归。
  偏色发生在**送显环节**，非选色/绘制逻辑。

### 5.2 根因三：显示用 PixelMap 未携带色彩空间信息

- `image.createPixelMapSync` 创建的 PixelMap 默认无色彩空间标记；
- ArkUI 组件（色卡 `.backgroundColor`、当前色块）按 sRGB 渲染；
- 广色域（Display P3）屏上，送显管线对未标记的画布/缩略图 PixelMap 按当前屏幕
  色彩空间解释像素 → 同一 0xAARRGGBB 值，画布显示与色卡显示偏色；
- 表现即「绘制的颜色跟画笔的颜色不一致」；sRGB 屏（模拟器/普通屏）上两者一致，
  故该问题仅在广色域设备上可复现。华为「显示规格」最佳实践亦要求
  「图片送显时做正确的色域转换和色域信息传递」。

### 5.3 修复内容（viewmodel/PixelMaps.ets 新增 + 8 处调用点替换）

- 新增 `PixelMaps.createSrgb(buf, w, h)` 工厂：createPixelMapSync(RGBA_8888) 后调用
  `pixelMap.setColorSpace(colorSpaceManager.create(ColorSpace.SRGB))`（API 12+ crossplatform，
  仅标记属性不改像素数据；标记失败静默退回默认行为）；
- 替换全部**程序生成 RGBA 数据 → 显示用 PixelMap** 调用点，钉死 sRGB 与 ArkUI 组件同域：
  CanvasView 画布（rebuildPixelMap）+ 棋盘格（buildChecker）、FrameStrip 帧缩略图、
  LayerPanel 图层缩略图、ProjectListPage/TemplateGallery 缩略图、ExportPanel 拼豆量化预览、
  ImageImportDialog 原图展示副本/转换结果预览；
- 不改：ExportPanel.packPng（PNG 文件打包，非显示）、ImageImportDialog 照片解码
  （source.createPixelMap，保留解码默认行为）。
